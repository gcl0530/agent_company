# Agent 创业公司操作系统

## 这是什么

这是一个让人和 Agent 协同交付定制软件的公司操作系统。公司的业务边界只有软件交付：前端、后端、自动驾驶算法、机器人自主作业算法以及必要的集成与运维能力，按项目组合。客户、软件形态、技术路线和部署环境都由具体项目定义。

本仓库的 MVP 不以目录数量或 Agent 数量衡量，而以一条可追溯的真实项目链衡量：

`机会/客户需求 -> 产品定义 -> 项目立项与计划 -> 研发与验证 -> 部署与验收 -> 复盘与能力沉淀`

Agent 是这条链中的受控执行者，不能自行作出客户承诺、发布决策或风险接受。

## 完整机制与按需启用

当前是初步设计阶段，仓库提供的是可演化的平台，不是要求每个项目执行一套固定大流程。公司级机制必须完整覆盖经营、产品、项目、研发质量、交付支持、组织能力、工具 Agent 与进化闭环；完整运行图见 [公司运转模型](company_operating_model.md)。

| 层级 | 内容 | 适用方式 |
| --- | --- | --- |
| 公司级完整机制 | 八条价值流、能力 owner、交接、质量门、运行节奏与人类治理 | 平台必须定义并持续维护，不因当前项目未使用而删除责任。 |
| 所有项目的最小原语 | 项目事实包、独立代码事实源、工作单元合同、人类审批边界 | 必须具备；具体内容按项目填写。 |
| 按需能力 | 设计证据、端到端交付切片、跨模块契约与评测资产、Agent 运行记录 | 只有出现外部设计输入、前后端/算法依赖、M1 以上 Agent 运行等触发条件时启用。 |
| 演化候选 | 视觉回归、性能预算、自动化追溯、更多 Agent 服务 | 先在真实项目试用并量化结果，不作为当前交付门槛。 |

前端、后端、自动驾驶算法、机器人自主作业算法和集成/运维是可组合能力面，不是预设部门或项目阶段。项目应选择最少但足以交付的能力与模板。

## 先从这里开始

1. 阅读 [产品定义](product_definition.md)、[总体设计](overall_design.md) 和 [实施计划](implementation_plan.md)，理解公司级边界。
2. 有客户线索后，先完成 [商机资格确认](0.4-Agent-客户与交付系统/templates/business_opportunity_template.md)，由人类业务负责人决定是否投入。
3. 获准进入产品澄清后，从 [项目模板](1.1-项目事实与交付档案/_template/README.md) 创建一个项目事实包。
4. 先完成项目包中的 `01_project_charter.md` 与 `02_product_brief.md`，再进入实施。
5. 用 [AGENTS.md](AGENTS.md) 为人和 Agent 配置工作单元、权限和升级路径。

## MVP 系统地图

| 系统 | 目录 | 在 MVP 中的职责 |
| --- | --- | --- |
| 组织与能力 | `0.0-Agent-组织与能力系统/` | 定义岗位、人机分工和能力缺口，不直接承担项目事实。 |
| 研发与质量 | `0.1-Agent-研发与质量系统/` | 设计、实现、测试与变更证据的通用质量门。 |
| 产品设计 | `0.2-Agent-产品设计系统/` | 将机会转化为问题、范围、需求与验收。 |
| 项目管理 | `0.3-Agent-项目管理系统/` | 维护计划、任务、风险、决策和节奏。 |
| 客户与交付 | `0.4-Agent-客户与交付系统/` | 管理商机资格确认、环境、交付包、验收和反馈回流。 |
| 工具链与 Agent 平台 | `0.5-Agent-工具链与Agent平台/` | 管理 Agent 工作单元、工具授权与可复用自动化。 |
| 迭代式 E 进化 | `0.6-Agent-迭代式E进化/` | 公司级 SOP、机制讲解与组织复盘参考。 |
| 传统方法对照库 | `1.0-传统方法-各方面集合/` | 传统公司的组织、运营与管理方法，用于提炼可被 Agent 化改造的机制。 |
| 项目事实与交付档案 | `1.1-项目事实与交付档案/` | 每个真实项目的总体方案、概览实施计划、交付结论与工程证据索引。 |

`1.0-传统方法-各方面集合/` 是公司方法对照库；`ref_docs/` 是外部参考输入；`Temp/` 是临时和历史备份。三者均不是当前项目事实源。

## 运行规则

- 每个项目在 `1.1-项目事实与交付档案/<project_id>/` 维护总体方案、概览计划、关键验证/交付结论和复盘；源码、详细设计、配置、CI、测试脚本及原始日志位于独立项目代码仓库。
- 每个工作单元必须有目标、输入、输出、质量门、权限、升级路径与沉淀位置。
- 未写明验收标准、负责人和风险边界的工作不得进入自主并行执行；未触发条件的扩展模板不要求填写。
- Windows 座舱、WSL、Linux 工控机是已知部署选项。只有项目确实使用时，才在项目包中定义模块落点、启动、日志、升级和回滚。

## 当前基线

当前仓库已完成公司 MVP 的结构和模板基线，尚未登记真实客户项目。`mine_command_center_demo` 是用于验证公司机制的内部样板，不是客户交付；它的反馈已写入 [样板项目反馈与机制试验](0.6-Agent-迭代式E进化/样板项目反馈与机制试验.md)。下一项有效工作是基于真实机会创建项目事实包，而不是继续扩展空目录或虚构需求。

当前基线的优势、缺口和建议顺序见 [Agent 公司操作系统评估](system_assessment.md)。
