# 传统公司方法对照库

## 作用

本目录收集和整理不依赖 Agent 的传统公司组织架构、经营运营方式、部门协作、项目管理、研发交付、人才管理和复盘机制。它不是待替换的旧资料，而是设计 Agent 创业公司时的对照基线：先理解传统机制解决了什么管理问题、依靠什么责任与约束运转，再判断哪些环节适合由 Agent 增强或自动化。

`0.0` 至 `0.6` 是基于 Agent 的公司运行系统；本目录提供它们的传统方法参照。`1.1-项目事实与交付档案/` 保存真实项目事实，两者不能相互替代。

## 建议分类

| 分类 | 关注问题 | 对应的 Agent 化系统 |
| --- | --- | --- |
| 公司治理与组织架构 | 岗位、权责、汇报关系、授权和决策 | `0.0` 组织与能力、`0.5` Agent 平台。 |
| 经营与运营机制 | 目标管理、经营节奏、指标、会议和复盘 | `0.3` 项目管理、`0.6` 迭代式 E 进化。 |
| 产品与客户机制 | 机会、需求、合同、客户反馈与验收 | `0.2` 产品设计、`0.4` 客户与交付。 |
| 研发与质量机制 | 设计、开发、测试、发布、质量与知识复用 | `0.1` 研发与质量、`0.6` 迭代式 E 进化。 |
| 人才与能力机制 | 招聘、培养、绩效、能力盘点和协作方式 | `0.0` 组织与能力。 |

## 使用规则

1. 记录方法的来源、适用规模、前提、优点、成本和失效边界，不只摘抄流程。
2. 抽取传统机制中的目标、责任、输入输出、决策权和质量门，再设计对应的 Agent 工作单元。
3. 不把传统流程原样自动化。Agent 化改造必须保留人类责任、权限边界和验证机制。
4. 已在真实项目中验证有效的结论，分别回写至 `0.0` 至 `0.6` 的对应系统；项目事实仍写入 `1.1-项目事实与交付档案/<project_id>/`。

本目录中的材料是方法论输入，不替代客户/业务原始证据、项目事实、代码、配置或验证记录。
