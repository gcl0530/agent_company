# 工程仓库与验证证据基线

## 作用

每个软件项目的代码仓库必须能回答：交付的是什么版本、如何复现、在哪个环境验证、观察到什么结果、还有什么边界。本基线适用于前端、后端、算法、集成和运维模块；项目只选择实际需要的验证项。

公司仓库保存项目概览和证据索引。源码、配置、CI、测试脚本、构建物、部署脚本和原始日志留在独立代码仓库，不能复制或拆散到项目事实包。

## 每个可验证基线应具备的记录

| 维度 | 最低记录 | 证据位置 | 质量门 |
| --- | --- | --- | --- |
| 版本 | 仓库、分支、提交或可解析版本号 | 项目包 `04` 与代码仓库 | 能定位到不可变基线 |
| 范围 | 对应需求、变更目标、非目标和受影响模块 | 需求/变更记录 | 不把未确认范围混入结论 |
| 可复现命令 | 安装、构建、测试、启动/停止命令及前置条件 | README、CI 或脚本 | 他人可按记录复做，失败可定位 |
| 验证环境 | 操作系统、运行时、浏览器/硬件/依赖版本及必要配置 | CI、测试报告或现场记录 | 环境与结论可关联 |
| 观察结果 | 预期、实际、证据链接、已知限制 | 测试报告、截图、日志或仪器记录 | 结论不只写“已测试” |
| 失败与回退 | 已知失败模式、降级、回退和升级人 | 变更记录、交付材料 | 风险不被成功结果掩盖 |

## 按模块选择验证

| 模块类型 | 通常需要的验证 | 额外关注 |
| --- | --- | --- |
| 前端/可视化 | 构建、关键交互、指定视口或目标设备、浏览器错误 | 包体、首屏、WebGL/静态降级、设计证据边界 |
| 后端/服务 | 单元/集成、接口契约、异常路径、日志 | 数据迁移、鉴权、并发、回滚 |
| 自动驾驶/机器人算法 | 数据集/仿真/回放、边界场景、指标与版本 | 安全边界、传感器/执行器假设、现场验证权限 |
| 集成/运维 | 安装、启动停止、配置、通信和故障恢复 | 环境权限、端口/网络、升级与回退顺序 |

未选择的模块不要求形式化产物；选择后不得仅以口头结论越过质量门。

## 视觉与交互验证的分级

视觉软件可按风险选择以下证据，均不替代客户验收：

1. 构建和静态检查：确认可打包、资源可解析、控制台无关键错误。
2. 浏览器或目标设备检查：确认关键画布/页面非空、交互可用、无明显遮挡或溢出。
3. 指定视口截图或视觉差异比对：仅在已有授权设计基线时使用，并保留基线版本。
4. 真实部署验证：在批准的座舱、工控机或现场环境中记录性能、兼容性和回退结果。

## 人类审批边界

Agent 可运行已授权的本地检查、整理结果和提交代码；是否接受失败风险、发布、部署、使用客户数据或宣布验收通过，必须由明确的人类负责人决定。

## 所有权与合并门

每个实际代码仓库在开始实施前按风险标出：模块/目录 owner、变更审查人、自动检查、受保护路径和发布批准人。前端交互、接口/数据模型、算法安全边界、部署配置和密钥路径不应由同一 Agent 在无复核情况下直接合并。可使用仓库原生的 CODEOWNERS、分支保护或等效机制；工具选择不是质量门本身，明确的人类 owner 与可追溯审查才是。
