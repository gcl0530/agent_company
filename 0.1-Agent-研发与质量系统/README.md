# 研发与质量系统

## 作用

本系统提供软件项目从设计到验证的通用工程机制。具体代码、配置和测试结果必须在代码仓库及项目包中留存；这里不替代项目实现事实。

## 最小工程链

`已确认需求 -> 设计与接口 -> 实现/配置变更 -> 模块验证 -> 集成/回归验证 -> 交付证据 -> 缺陷与复盘回写`

项目按需要选择前端、后端、自动驾驶算法、机器人自主作业算法及集成/运维模块。没有被选择的模块不应产生形式化工作。

## 最低质量门

- 变更有对应需求、设计或明确的缺陷修复依据。
- 可执行变更有代码位置、配置影响、测试结果和已知限制。
- 涉及部署、通信、控制或安全时，明确输入输出、失效处理和验证范围。
- 无法自动验证的现场结论须记录环境、步骤、现象和证据位置。

使用 [工程变更与验证模板](engineering_change_template.md) 统一记录项目级工程证据。
