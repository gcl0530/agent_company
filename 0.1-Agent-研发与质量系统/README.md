# 研发与质量系统

## 作用

本系统提供软件项目从设计到验证的通用工程机制。详细设计、代码、配置、CI、测试脚本、构建产物和原始测试结果必须在独立项目代码仓库中留存；项目包只记录概览、关键结论和证据链接。

## 最小工程链

`已确认需求 -> 设计与接口 -> 实现/配置变更 -> 模块验证 -> 集成/回归验证 -> 交付证据 -> 缺陷与复盘回写`

项目按需要选择前端、后端、自动驾驶算法、机器人自主作业算法及集成/运维模块。没有被选择的模块不应产生形式化工作。

## 最低质量门

- 变更有对应需求、设计或明确的缺陷修复依据。
- 可执行变更有代码位置、配置影响、测试结果和已知限制。
- 涉及部署、通信、控制或安全时，明确输入输出、失效处理和验证范围。
- 无法自动验证的现场结论须记录环境、步骤、现象和证据位置。

使用 [工程变更与验证模板](engineering_change_template.md) 记录一次变更的方案与结果，并以 [工程仓库与验证证据基线](engineering_evidence_baseline.md) 检查项目是否具备可定位版本、可复现命令、环境和观察结果。

跨前端、后端、算法或部署模块时，使用 [跨模块契约与评测资产模板](cross_module_contract_and_evaluation_template.md) 定义语义、兼容性、失败处理和可版本化的评测场景；不以口头联调替代契约和证据。
