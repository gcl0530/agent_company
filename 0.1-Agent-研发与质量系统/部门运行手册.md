# 研发与质量系统运行手册

## 部门使命

将已确认的项目需求变成可定位、可验证、可交付的软件变更。研发系统对代码、配置和测试证据负责，不替代产品范围和客户验收。

## 能力单元

| 能力单元 | 主要职责 | 必须输出 | 放行条件 |
| --- | --- | --- | --- |
| 技术负责人 | 模块边界、架构取舍、接口和风险 | 设计结论、接口约束、变更影响 | 关键取舍有负责人和证据。 |
| 前端/客户端 | 交互、状态、客户端集成 | 代码、构建与验证记录 | 满足需求和兼容性口径。 |
| 后端/平台 | 服务、数据、接口、权限与运维 | 代码/配置、接口与运行证据 | 接口、数据和失败处理明确。 |
| 自动驾驶/机器人算法 | 算法能力、输入输出、边界与安全处理 | 方案、参数、离线/仿真/现场证据 | 适用范围与失效处理明确。 |
| 测试与质量 | 风险分析、测试设计、缺陷和回归 | 测试记录、缺陷状态、质量结论 | 通过约定门槛或完成豁免审批。 |
| 集成与发布支持 | 构建、依赖、环境、版本与回退 | 发布基线、部署与回滚证据 | 交付环境可复现。 |

项目只启用实际需要的单元，不因目录存在而强制全部参与。

## 变更运行链

`已确认需求/缺陷 -> 设计与接口 -> 实现或配置变更 -> 模块验证 -> 集成/回归 -> 交付证据 -> 复盘`

每项变更至少关联需求或缺陷、代码位置、配置影响、验证证据和遗留边界。Agent 可辅助调研、实现、测试生成和证据整理，但测试绿灯不自动等于可交付。

## 质量与升级

- 发生接口不确定、数据缺失、测试失败、环境差异或安全风险时，升级技术与项目负责人。
- 涉及座舱、WSL、工控机、控制、通信或算法安全边界时，记录输入输出、故障处理、版本兼容和目标环境验证。
- 高风险变更必须有人工评审和回退方案；无法覆盖的风险须在交付前明确接受人。
