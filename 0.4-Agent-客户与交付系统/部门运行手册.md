# 客户与交付系统运行手册

## 部门使命

管理从客户/业务事实到软件交付、现场验收和反馈回流的外部接口。它不替代研发验证，也不在没有证据时宣布客户已验收。

## 核心职责

| 职能 | 输入 | 输出 | 质量门 |
| --- | --- | --- | --- |
| 机会资格确认 | 客户线索、问题描述、已有关系与约束 | 商机记录、待确认项、是否投入产品澄清的建议 | 有来源、业务 owner 和下一步；未确认项不伪装为需求。 |
| 商务与承诺控制 | 范围、交期、报价/合同、数据与现场风险 | 人类审批记录、可对外沟通边界 | Agent 不作承诺；关键条件由人类负责人确认。 |
| 环境澄清 | 目标设备、网络、接口、运维约束 | 环境与部署边界 | 不确定项列为风险或待确认。 |
| 交付准备 | 版本、依赖、配置、测试结果 | 交付清单、操作与回滚说明 | 可定位、可安装、可启动、可回退。 |
| 部署支持 | 现场事实、日志、执行步骤 | 部署记录、问题与处理 | 实际环境与版本可追溯。 |
| 验收与反馈 | 验收标准、现场结果、客户意见 | 验收记录、遗留项、下一轮输入 | 结论有证据和人类审批。 |

## 目标环境原则

若项目使用 Windows 座舱、WSL 或 Linux 工控机，必须在项目事实包中明确组件落点、进程/服务、依赖、网络或串口权限、配置、日志、启动顺序、升级和回滚。未使用这些环境的项目不需要填写其专用项。

## 从机会到项目的边界

1. 线索先使用 [商机资格确认模板](templates/business_opportunity_template.md) 记录来源、问题、价值、约束和待确认项。
2. 业务负责人决定是否投入产品澄清；此时仍不代表报价、合同或项目立项。
3. 产品负责人确认问题、范围和验收草案后，项目负责人才能在 `1.1-项目事实与交付档案/` 创建项目事实包。
4. 报价、合同、客户敏感信息、部署窗口和最终验收均由明确的人类负责人审批。

## 升级条件

- 客户承诺、验收标准或现场权限不清。
- 部署步骤不可复现、无法回滚，或版本与验证证据不一致。
- 发现安全、数据、网络或设备控制风险。
