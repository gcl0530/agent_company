# 客户与交付系统

## 作用

本系统连接客户需求、客户现场与公司内部产品、项目和研发能力。它负责澄清需求和软件形态，组织软件交付、记录验收与反馈，并将外部事实回流到产品和项目决策。Windows 座舱和 Linux 工控机是当前已知项目环境，不是每个软件项目的固定前提。

## 输入与输出

| 输入 | 输出 |
| --- | --- |
| 客户需求、现场问题、软件形态/目标环境、可交付版本、开发与验证证据 | 客户需求证据、软件交付范围、部署方案、验收记录、现场问题、客户反馈、下一步需求和复盘输入 |

## 最小工作流

`客户软件需求 -> 问题与软件形态澄清 -> 产品定义 -> 项目协同 -> 软件交付准备 -> 现场/客户验收 -> 反馈与下一轮需求`

## Agent 工作单元

- 客户研究 Agent：整理公开资料、访谈纪要和现场记录，明确证据等级与待确认项。
- 交付准备 Agent：核对版本、配置、脚本、操作说明、已知边界和验收清单。
- 交付反馈 Agent：把现场问题按“可复现/仅现场、功能缺陷/体验优化、影响范围/证据”结构化回写。

软件交付项目应单独记录 Windows 座舱/WSL/Linux 工控机部署拓扑、依赖、配置、服务、日志和回滚。任何对外报价、合同、交付承诺、客户敏感信息处理和最终验收结论必须由明确的人类负责人审批。
