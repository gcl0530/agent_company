# 工具链服务目录

## 服务原则

工具服务由部门结果驱动。提出者先说明当前人工摩擦、受影响角色、预期结果、输入事实源、权限边界和验收指标；工具链负责人再决定采用脚本、确定性工作流、半自主 Agent 或不建设。

| 服务 | 服务对象 | 输入 | 输出 | 人工控制点 | 当前状态 |
| --- | --- | --- | --- | --- | --- |
| 项目事实包创建 | 产品、项目管理 | 项目编号 | 标准项目目录与六份模板 | 人类确认立项后运行 | 可用 |
| 项目包完整性检查 | 项目管理、交付 | 项目目录 | 缺失文件报告 | 不判断内容是否真实或批准项目 | 可用 |
| 项目证据基线检查 | 产品、项目、研发、交付 | 已填写的项目事实包 | 代码基线、交付基线、需求、里程碑和工作单元缺口 | 不访问客户系统，不判断质量结论，不替代人类审批 | 可用 |
| Markdown 链接检查 | 全部门 | 仓库或指定路径 | 失效本地链接报告 | 不自动修正文档 | 可用 |
| 需求到交付追溯检查 | 产品、项目、研发、交付 | 项目包、代码/测试位置 | 断链提示 | 需要真实项目后设计 | 待验证 |
| 工程验证编排 | 研发与质量 | 测试命令、环境和预期 | 可重复验证记录 | 不能替代测试负责人结论 | 待验证 |
| 交付就绪检查 | 客户与交付 | 版本、配置、部署和验收项 | 检查清单与缺口 | 发布与验收仍由人批准 | 待验证 |
| Agent 工作单元运行记录 | 各部门 | 已注册工作单元、任务和证据 | 使用、成本、质量和升级记录 | owner 审核是否复用/下线 | 待验证 |
| 跨模块契约与评测资产登记 | 研发、算法、项目管理 | 交付切片、接口/数据/模型依赖、样本与阈值 | 契约、兼容性、失败语义与评测缺口 | 不替代架构批准、数据授权或安全评审 | 可用 |
| 端到端交付切片编排 | 产品、项目、研发、交付 | 已确认需求和参与模块 | 可演示结果、集成 owner、验收与风险记录 | 不替代详细任务拆分或发布审批 | 可用 |
| Agent 成熟度评估 | 各部门、工具链 | 工作单元、任务样本和运行记录 | 等级、可用动作、晋级/降级决定 | 人类 owner 批准，不能自动晋级 | 可用 |

## 服务生命周期

`部门请求 -> 工具链澄清 -> 小范围试用 -> 度量结果 -> 标准化/修改/下线 -> 复盘回写`

没有明确服务对象、结果指标或权限边界的请求，不进入开发。
