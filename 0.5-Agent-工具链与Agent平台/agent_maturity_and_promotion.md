# Agent 成熟度与权限晋级

## 原则

Agent 的权限不由模型宣传、演示效果或单次成功决定，而由**在明确任务范围内持续可复现的结果、失败处理和人类审查负担**决定。成熟度可以按工作单元分别评估，同一 Agent 在不同任务上的等级可以不同。

## 等级

| 等级 | 可承担动作 | 必须控制 | 不允许承担 |
| --- | --- | --- | --- |
| M0 协作草案 | 调研、摘要、方案草案、问题归纳 | 不写入正式事实源；标明事实与假设 | 对外沟通、代码/配置修改、执行命令。 |
| M1 受审查工件 | 在明确位置生成文档、测试草案、代码建议或检查报告 | 人工质量门后才能进入正式事实或实施 | 自主发布、客户承诺、不可逆修改。 |
| M2 受控内部操作 | 在受限仓库/环境运行确定性脚本，或完成可回退的内部动作 | 权限白名单、日志、停止条件和 owner 抽查 | 生产环境、客户数据外发、商业/安全决定。 |
| M3 项目工程协作 | 在分支或隔离环境实施代码/配置变更并运行约定验证 | 任务合同、测试、代码审查、合并/发布人工批准 | 绕过评审直接交付或改变项目范围。 |
| M4 有限自动化服务 | 对低风险、高频、可回滚任务自动运行 | 持续监控、阈值、告警、停用开关和定期复评 | 高风险部署、价格/合同、客户验收、不可回退控制动作。 |

当前公司默认从 M0/M1 起步。M2 及以上必须有真实任务证据；M4 不是当前默认目标。

## 晋级合同

| 证据 | 要求 |
| --- | --- |
| 任务范围 | 明确输入、输出、工具、权限和不做什么。 |
| 测试样本 | 包含正常、边界、失败或信息不足场景。 |
| 质量结果 | 记录成功率、人工修正率、失败类型、成本和耗时。 |
| 失败处理 | 明确何时停止、如何升级、如何回退。 |
| 审批 | 人类 owner 依据证据批准特定任务范围内的晋级。 |

任何范围扩大、模型/工具变更、质量显著下降、异常成本、权限事故或客户风险都触发重新评估；必要时立即降级到 M0/M1 或停用。

## 与部门的关系

- 产品和商务类 Agent 默认停留在 M0/M1，不能对外承诺。
- 项目管理 Agent 可在 M1/M2 做状态整理和确定性检查，不替代风险决定。
- 研发 Agent 可在 M1/M3 协作，但合并、发布和安全取舍保持人工批准。
- 交付 Agent 可做清单与证据检查，不直接操作客户环境，除非项目明确授权并满足 M2 以上条件。
