# 组织与能力系统运行手册

## 部门使命

让每个项目在需要时获得明确的人类责任、所需专业能力和受控的 Agent 支持。该系统不替客户决定产品范围，也不替项目经理排期。

## 核心职责

| 职能 | 输入 | 输出 | 质量门 | 负责人 |
| --- | --- | --- | --- | --- |
| 角色配置 | 项目立项、能力缺口 | 项目角色表、人机分工 | 每项关键责任有一名人类 owner | 业务/项目负责人 |
| 能力盘点 | 项目结果、代码/交付证据 | 能力矩阵、培养或招聘动作 | 结论关联真实工作证据 | 组织负责人 |
| Agent 负责人配置 | Agent 工作单元与风险级别 | Agent owner、权限与升级人 | 无 owner 或无升级人不得启用 | 部门负责人 |
| 复盘回流 | 项目复盘、质量问题 | 角色卡与能力模型更新 | 只沉淀已验证结论 | 组织负责人 |

## 项目启动检查

1. 明确业务、产品、项目、技术和交付责任人；小团队可一人兼任，但责任不能空缺。
2. 为所选前端、后端、算法、测试/交付能力指定 owner 与替补方式。
3. 为 Agent 指定人类负责人、可用工具、写入范围和升级条件。
4. 将未具备的能力记录为风险、外部协作或培养任务，不以 Agent 名称掩盖能力缺口。

## 运行节奏

- **项目启动时**：完成角色与能力模板。
- **每两周**：项目负责人确认能力缺口是否影响里程碑。
- **项目复盘时**：用实际结果更新能力结论、培训主题与 Agent 工作单元。

## 升级条件

- 无人可对客户承诺、架构、发布或安全风险负责。
- 关键任务需要的技能、设备、数据或权限不存在。
- Agent 输出持续无法达到质量门，或人工审查负担超过收益。
