# 产品设计系统运行手册

## 部门使命

将客户或业务机会转化为边界清楚、可实施、可验收的软件问题定义。产品系统不替代项目排期、技术架构或交付验收。

## 核心职责

| 职能 | 输入 | 输出 | 质量门 |
| --- | --- | --- | --- |
| 机会澄清 | 客户访谈、现场问题、业务数据 | 问题陈述、证据与待确认项 | 事实和假设分开记录。 |
| 场景与价值 | 用户、任务流、现有痛点 | 场景、目标结果、价值假设 | 说明为谁解决何问题。 |
| 需求与边界 | 场景、约束、技术反馈 | 需求、优先级、非目标 | 每条关键需求有验收方式。 |
| 需求变更 | 新反馈、风险、实施发现 | 变更决定、影响与优先级 | 未确认变更不得直接进入研发。 |

## 运行节奏

- **立项前**：形成最小产品简报，确认问题、目标、范围、非目标和验收。
- **实施期间**：需求变更先登记影响，再由产品与项目负责人决定。
- **交付后**：将客户/现场反馈区分为缺陷、体验优化、新机会或环境问题，回写下一轮需求。

## Agent 使用边界

产品 Agent 可整理访谈、研究公开资料、归纳需求、维护追溯；不得把推测写成客户事实，不得自行承诺功能、价格、交期或验收结论。
