# 产品定义系统

## 作用

本系统把客户软件需求转化为可验证的产品定义。它回答：为谁解决什么问题、软件形态是什么、需要哪些前端/后端/算法模块、运行环境是什么、预期结果是什么、哪些内容不做，以及研发和交付如何验收。

## 输入与输出

| 输入 | 输出 |
| --- | --- |
| 客户需求、软件形态/目标环境、现场反馈、业务约束、已有能力 | 产品简报、场景定义、需求 Backlog、模块选择、优先级、验收标准、项目边界、非目标和待验证假设 |

## 最小工作流

`机会证据 -> 场景/用户 -> 问题与价值假设 -> 最小需求 -> 验收标准 -> 进入项目计划 -> 客户结果回流`

## Agent 工作单元

- 市场研究 Agent：整理机会、客户、竞品和场景证据；不能将推测写成客户事实。
- 产品分析 Agent：将证据整理为问题、需求、非目标和验收草案；由产品负责人确认优先级和对外承诺。
- 需求追踪 Agent：维护需求到项目、研发、测试和交付结果的追溯关系；发现断链时升级项目负责人。

## 首个项目必须建立的文件

1. `product_brief.md`：目标客户、场景、问题、价值、约束和非目标。
2. `requirements.md`：需求、优先级、验收标准和待验证假设。
3. `decision_log.md`：关键取舍、证据、负责人和日期。

没有已确认的客户/业务机会时，不在本目录虚构产品需求。
