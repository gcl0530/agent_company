# 项目管理系统

## 作用

本系统把已确认的产品目标组织为可执行、可跟踪、可升级和可复盘的项目。它不重新定义产品价值，也不替代研发设计，而是保证目标、任务、依赖、风险和结果不断链。

## 输入与输出

| 输入 | 输出 |
| --- | --- |
| 产品定义、验收标准、前端/后端/算法和运行环境约束、交付窗口、人员和 Agent 能力 | 项目计划、任务合同、软件架构/部署方案、里程碑、风险清单、问题管理表、决策记录和复盘 |

## 最小工作流

`产品目标 -> 二级任务拆解 -> 人/Agent 合同 -> 执行与刷新 -> 风险/问题升级 -> 交付验收 -> 复盘`

## 管理规则

- 每个任务必须有目标、负责人、Agent 参与方式、输入、输出、验收、依赖和风险；涉及交付时还必须说明所选前端/后端/算法模块、目标环境、版本、运行/部署方式和回滚责任。
- 新任务先判断是否已被现有二级任务覆盖；没有覆盖时，先上表再进入执行。
- 计划表和问题管理表至少每两天刷新一次；无进展时也要记录现象、原因和下一步。
- 强依赖落后、现场交付窗口和客户风险会自动提高优先级。
- 重大范围变更、客户承诺、风险接受和资源调整必须升级给人类负责人决策。

## 首个项目必须建立的文件

1. `project_plan.md`
2. `task_contracts.md`
3. `risk_and_issue_log.md`
4. `decision_log.md`
5. `retrospective.md`
