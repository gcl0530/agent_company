# 项目管理系统运行手册

## 部门使命

把产品定义组织成可执行的结果链，持续维护目标、责任、依赖、风险、决策和节奏。项目管理不替代产品优先级、技术方案或测试结论。

## 核心职责

| 职能 | 输入 | 输出 | 质量门 |
| --- | --- | --- | --- |
| 立项与计划 | 产品简报、能力、交付窗口 | 里程碑、任务、依赖、资源假设 | 每项关键结果有 owner 与放行条件。 |
| 任务合同 | 目标、接口、约束 | 人/Agent 工作单元 | 输入输出、权限、升级和质量门完整。 |
| 风险与问题 | 执行状态、测试、客户反馈 | 风险/问题日志、升级动作 | 高影响项有责任人和截止时间。 |
| 决策与变更 | 范围/资源/技术/交付影响 | 决策记录、计划更新 | 决策人和依据可追溯。 |
| 复盘推进 | 交付结果、实际工时、反馈 | 改进任务与归属 | 每项改进有落点和验证方式。 |

## 节奏

- **启动会**：确认项目立项、工作单元、风险和首个里程碑。
- **每周项目推进**：更新已完成、阻塞、下周目标、风险和决策需求。
- **质量/交付前检查**：核对需求、代码、测试、环境与交付事实是否能追溯。
- **交付后复盘**：将改进任务写入对应部门或 `0.6` 机制试验。

## 自动化支持需求

项目管理可以向 `0.5` 请求项目包创建、完整性检查、状态汇总、风险提醒或追溯检查。请求必须定义要减少的人工摩擦和验收指标，不能只提出“做一个 Agent”。
